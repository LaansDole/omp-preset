# omp-preset

My portable setup for [Oh-My-Pi](https://github.com/can1357/oh-my-pi) (`omp`).
Clone it, run one script, and a new machine has the same settings, agents,
skills, and plugins as this one.

It is **not a fork** of omp. You always run the latest omp; this repo only carries
the personal layer on top (config, agents, skills, plugin list).

## Quick start

```bash
git clone https://github.com/LaansDole/omp-preset.git ~/omp-preset
cd ~/omp-preset
./bootstrap.sh                 # installs into the default profile
```

Then sign in to Anthropic. Your login lives in `~/.omp/agent/agent.db`, which
`bootstrap.sh` never copies, so a new machine starts signed out:

```bash
omp login anthropic            # or type /login inside omp
```

Done. Start `omp` as usual.

> Want an isolated profile instead? `OMP_PROFILE=work ./bootstrap.sh`

## What you get

| Piece | File | What it does |
|---|---|---|
| Settings | `config.yml` | Model roles, advisor, browser, statusline, task overrides |
| Task agents | `agents/` | Custom subagents omp can spawn (see [Agents](#agents)) |
| Advisor rules | `WATCHDOG.md` | Keeps the advisor quiet unless it has real, verified evidence |
| Skills | `skills/` | `writing-pr-descriptions`, `auditing-worktrees`, `sweeping-merged-worktrees` |
| Plugins | `plugins.json` | Plugins reinstalled by reference (never copies `node_modules`) |

## Key settings at a glance

**Models** (`modelRoles`)

| Role | Used for |
|---|---|
| `default` | Main agent |
| `slow` | Heavy reasoning, security review |
| `smol` | Quick/cheap jobs (`init`, scouting) |
| `advisor` | Background reviewer (mid-tier on purpose: it runs every turn) |
| `plan`, `designer` | Planning and UI design |

**Browser runs headless** (`browser.headless: true`). Subagents use the browser
in the background, so Chrome for Testing never jumps in front of your work.
Want to watch one run? Ask omp to open that page with `headed: true`. Only that
call gets a visible window.

**Advisor** (`advisor.enabled: true`) is a passive reviewer that only speaks up
for real problems (see `WATCHDOG.md`). It also watches the `scout` and
`reviewer` subagents (`task.agentAdvisor`).

**Statusline** shows model, context %, and git branch:

```yaml
display:
  showTokenUsage: true
statusLine:
  contextLine: percentage                # off | percentage | annotated | embedded
  rightSegments: [model, context, git]   # also: path, cost
```

## What bootstrap.sh does

1. Backs up your existing `config.yml` to `config.yml.preset-bak` (first run only).
2. Copies `config.yml`, `agents/*.md`, and `WATCHDOG.md` into your omp agent dir:
   `~/.omp/agent`, or `~/.omp/profiles/<name>/agent` with `OMP_PROFILE`,
   or `$PI_CODING_AGENT_DIR` if set.
3. Copies `skills/*` into `~/.agents/skills/` (the `pr` agent reads its skill from there).
4. Reinstalls each plugin in `plugins.json` with `omp plugin install`.

It never touches machine-specific files.

## Never committed (machine-specific or secret)

`agent.db*` (login credentials), `history.db`, `models.db`, `sessions/`, `logs/`,
`cache/`, `blobs/`, `install-id`, `autoqa.db`, `.env` (API keys).
`.gitignore` already covers these.

## Optional: install as an omp package

The repo is also an omp/pi package, which is handy for agents and skills only:

```bash
omp plugin link ~/omp-preset      # live: edits apply without reinstall
# or
omp plugin install ~/omp-preset   # one-time copy
```

| Piece | Package install | bootstrap.sh |
|---|---|---|
| Agents | yes | yes |
| Skills | yes | yes |
| `config.yml` / `WATCHDOG.md` | no | yes |
| Plugins | no | yes |

Use `bootstrap.sh` for the full setup. Use the package link if you only want
agents and skills to stay in sync while you edit them.

## Advanced: advisor judge gate

`advisor.judgeGate: true` lets the `judge` model role pre-screen advisor updates
(destructive / guessing / looping / shortcut). Low-risk steps skip review and get
batched into the next one; final updates are always reviewed.

- Needs an omp build with the `feat/advisor-judge-gate` change; release omp ignores the key.
- Watch decisions:
  `tail -F ~/.omp/logs/omp.$(date +%F).*.log | grep --line-buffered "advisor review gate"`

## Updating

- **Pull changes from this repo:** `git pull && ./bootstrap.sh`
- **omp released a new version:** run `omp config list` to see current keys,
  fix anything in `config.yml` that warns, then commit. Unknown keys only cause
  warnings, and omp auto-migrates old config, so drift is easy to recover from.
- **Keep this repo small.** Fewer custom keys means less breaks when omp changes.
  For per-project tweaks, layer an overlay (`omp --config <file>` or
  `PI_CONFIG_FILES`) instead of growing `config.yml`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Chrome for Testing keeps grabbing focus | Check `omp config get browser.headless` is `true`, restart omp, quit the leftover Chrome window |
| Login errors, or a different model than expected runs | Your Anthropic login expired. Run `omp login anthropic` again |
| A plugin fails to install | Rerun `omp plugin install <ref>`, then check `omp plugin doctor` |
